# 献立の AI 補助（任意・既定 OFF）

実装: `src/lib/meals/ai.ts`（サーバー専用アダプター）、単体テスト: `src/lib/meals/__tests__/ai.test.ts`。
要件: `docs/plans/2026-11-10-household-chores/requirements-ledger.md` の C-81〜C-89。

## 位置づけ

献立の中核は**自動献立**（アプリ内の規則ベースの処理）で、外部 AI が無くてもすべての機能が動く。
生成 AI が行うのは次の 2 つだけで、画面と報告では「自動」と「AI 補助」を分けて示す。

- 希望文（例:「金曜はカレー。魚を多めに」）を構造化する
- 候補の料理 ID を選ぶ・並べ替える

材料の数量、アレルゲン、年齢制約、固定枠、在庫、買い物の正本はアプリ側にある。AI の応答から DB を直接更新したり、
外部で購入したりする経路は無い。AI は料理の作り方・栄養・子ども向けの助言を生成しない（返ってきても受け取らない）。

AI の結果は、規則ベースの解釈（`wish-rules`）で読めた希望へ**足す**（`mergeWishConstraints`。置き換えない）。
規則が読めた固定（「金曜はカレー」）や時間の上限は、AI がそれを返さなくても残る。AI が同じ日・同じ区分へ別の料理を
固定しても規則の固定を残し、AI の分で何も増えなければ「AI 補助で読み取った」とは表示しない。

AI を呼ぶのは、規則で**読めなかった**部分が残ったときだけ。同じ日・同じ区分への 2 つ目の固定
（「金曜はカレー、金曜は親子丼」の 2 つ目）は、規則が読んだうえで固定にしなかった希望で、読めなかった部分ではない。
これだけのためには AI を呼ばず（回数も使わない）、`pinConflicts` として利用者へ返す。

## 「無料」の意味

- 使うのは Cloudflare Workers AI の無料枠（[料金](https://developers.cloudflare.com/workers-ai/platform/pricing/)）。
  アカウント全体で 1 日 10,000 Neurons、毎日 00:00 UTC（**日本時間 9:00**）にリセットされる。
- **Workers Free** では無料枠を超えた呼出しはエラーになるだけで、課金されない。
- **Workers Paid** では超過分が課金される（1,000 Neurons あたり $0.011）。**Paid のアカウントでは有効化しない。**
- 経路は REST の直接呼出し `https://api.cloudflare.com/client/v4/accounts/{id}/ai/run/{model}` の 1 本だけ。
  AI Gateway（Unified billing・プリペイド・自動補充）、別の provider、有料モデル、有料 fallback は実装していない。
  失敗したときに別の API へ切り替える処理も無い。
- 「無料」はこの機能が追加の請求を発生させない、という意味であり、上の前提（Workers Free であること）に依存する。
  アプリはアカウントのプランを判定できない。

## 有効化の前提（人が実施する）

アカウントが Workers Free か Paid かを API で判定する公式の方法は確認できていない
（2026-11-11 に料金・制限・エラー・REST API の各ページを確認）。次を**人が**行ってから有効化する。

1. Cloudflare ダッシュボードで、対象アカウントの Workers のプランが **Free** であることを目で確認する。
   Paid だった場合・判断できない場合は有効化しない（台帳 C-82 は `blocked` のまま）。
2. 権限が `Workers AI - Read` と `Workers AI - Edit` だけの API トークンを作る。
3. Workers AI のダッシュボードで当日の Neurons 使用量を見て、他の用途と合わせて無料枠に収まるかを確かめる。
4. 使うモデルのページで利用条件を確認する（既定モデルは下記）。
5. サーバー側の環境変数を設定する。

| 変数 | 内容 |
| --- | --- |
| `MEAL_AI_ENABLED` | `true` と完全一致のときだけ ON |
| `MEAL_AI_ACCOUNT_ID` | Account ID（32 桁の hex） |
| `MEAL_AI_API_TOKEN` | 上の API トークン |
| `MEAL_AI_MODEL` | 任意。空なら `@cf/meta/llama-3.3-70b-instruct-fp8-fast` |
| `MEAL_AI_JSON_MODE` | 任意。`json_schema`（既定）/ `json_object` / `off` |

値が 1 つでも欠ける・形式が違う場合は呼び出さない（`misconfigured`）。ニュース用の `NEWS_AI_*` へはフォールバックしない。
ダッシュボードの画面名や位置は変わりうるため、この文書では操作手順を画面単位で固定していない。

## 無料枠はニュースの AI と共有する

地域ニュースの AI 補助（`NEWS_AI_*`、`docs/runbooks/regional-news.md`）と同じ Account ID を使うと、
両方が同じ 10,000 Neurons/日 から引かれる。ニュース側の 1 日 20 回の上限は献立側の計上とは別で、
合算した上限はアプリには無い。献立側で無料枠の枯渇を検知しても、ニュース側の呼出しは止まらない
（ニュース側は失敗を原文表示へ戻すだけで、課金経路は持たない）。

## 回数の上限と retry

- 世帯ごとに 1 日 10 回まで。**retry も 1 回として数える。** 計上は呼出しの直前に毎回行い、失敗した呼出しも消費する。
- 1 回の操作で provider を呼ぶのは最大 2 回（初回 + retry 1 回）。1 呼出しの timeout は 8 秒。
- retry するのは timeout、5xx、内部コード 3040（一時的な容量不足）、不正な出力だけ。
- 計上できなかったとき（DB の障害など）は呼び出さない。
- 入力の上限: 希望文 200 字、対象日 7 日、候補 60 件。応答は 32KB、出力は 600 トークンまで。

## 上限に達したとき（3036）

無料枠の枯渇（内部コード 3036）と一時的な混雑（3040）は**どちらも HTTP 429** で返る。
アダプターは本文の内部コードを読んで区別し、429 だけでは枯渇と判断しない。

| 応答 | 扱い |
| --- | --- |
| 3036（日次無料枠の枯渇） | retry しない。次の 00:00 UTC（**9:00 JST**）まで全世帯の AI 呼出しを止める印を書く（service role 専用 RPC `mark_dinner_ai_exhausted`）。アダプターは再開時刻（`resetsAt`）を返す |
| 3040（一時的な容量不足）・コード不明の 429・5xx | 1 回だけ retry。停止の印は書かない |
| 401 / 403 / 404 / 410、5035（Paid 必須モデル）、5028（廃止モデル）など | 設定の問題。retry しない。ログに HTTP ステータスと内部コードを残す |
| その他の 4xx | retry しない |

どの場合も**自動献立はそのまま続く**。アダプターは例外を投げず「使えなかった」ことと理由を返すので、
呼び出し側は希望文を規則ベースの解釈で扱い、AI を使っていない結果として示す。
停止の印を書けなかった場合も利用者の操作は失敗させない（次の操作がもう一度 3036 を受けて書き直す）。

世帯の「1 日 10 回」の日付の境界は回数計上の RPC `claim_dinner_ai_call`
（`supabase/migrations/20261111100003_dinner_tables.sql`）が決める。2026-11-11 時点の定義は UTC の日付で、
無料枠のリセットと同じ 9:00 JST 区切り。停止中は回数を計上しない。

## 送るデータと送らないデータ

送るのは次の 3 つだけ。

- **希望文**（利用者の自由入力。制御文字を除き 200 字まで）
- **対象日と曜日**（最大 7 日）
- **候補の料理**の ID・料理名・タグ（最大 60 件。**アレルギー・苦手の除外を適用した後**のもの）

送らないもの: 氏名、生年月日・月齢、育児記録、診断名、アレルギー・苦手の内容、在庫、世帯 ID・利用者 ID、認証情報。
これらは入力の型に存在せず、呼び出し側が誤って付けても送信内容へ写らない（テストで固定）。

注意: 希望文は利用者が自由に書けるため、利用者自身が個人情報を書けば送られる。アダプターは希望文の中身を判定しない。
名前や病名を書かないよう促す案内は、入力欄（画面側）で行う。

希望文は命令ではなくデータとして扱う。system 文は固定で、希望文や料理名を連結しない。
Cloudflare の[データ利用条件](https://developers.cloudflare.com/workers-ai/platform/data-usage/)は運用者が確認する。

## 応答の扱い

応答は候補の ID・対象日・候補に現れるタグだけで検証する。候補に無い料理 ID、範囲外の日付、
同じ日の重複した固定、余分な項目、範囲外の調理時間が 1 つでもあれば、**応答全体を採用しない**
（要素単位で落として残りを採用する方式ではない）。採用しなかったときは規則ベースの解釈へ戻る。
採用する側（Server Action）は、必須除外と献立の版をもう一度検証してから反映する。
応答はキャッシュしない。

## モデルを変える

`MEAL_AI_MODEL` に `@cf/<提供元>/<モデル>` の形で指定する。この形以外と、公式が Workers Paid 必須と明記しているモデルは
設定の時点で拒否する（一覧は変わりうるので、実行時の 5035 も設定の問題として扱う）。

- 既定の `@cf/meta/llama-3.3-70b-instruct-fp8-fast` は JSON Mode の公式対応リストにある（2026-11-11 確認）。
- JSON Mode に対応しないモデルでは `MEAL_AI_JSON_MODE=json_object` または `off` にする。
  文字列で返る JSON（前後に説明やコードフェンスが付いたもの）も同じ検証を通して解釈する。
- モデルを変えると Neurons の単価が変わる。変更後は使用量を確認する。

消費の目安（**未実測の概算**。既定モデルの単価は入力 26,668・出力 204,805 Neurons / 100 万トークン）:
候補 60 件・出力上限いっぱいの最悪の場合で 1 呼出し 200 Neurons 前後、アカウント全体で 1 日 50 呼出し程度。
実際の値は実 API 試験で確かめる。

### 廃止モデル（410 / 5028）への対応

Cloudflare はモデルを一括で廃止することがある（廃止後は HTTP 410・内部コード 5028）。

1. サーバーログの `[meal-ai]` で `event: "misconfigured"`、`httpStatus: 410`、`providerCodes: [5028]` を確認する。
2. Cloudflare の changelog とモデル一覧で移行先を選び、無料で使えること・JSON Mode の対応を確認する。
3. `MEAL_AI_MODEL`（必要なら `MEAL_AI_JSON_MODE`）を更新する。コードの変更は要らない。
4. それまでの間、AI 補助は使えないが自動献立は動き続ける。

## ログ

失敗時に `[meal-ai]` の構造化ログを出す。含むのは種類、試行回数、モデル名、HTTP ステータス、内部コードだけ。
希望文、API トークン、Account ID は含めない。

## 止める・戻す

`MEAL_AI_ENABLED` を外す（または `true` 以外にする）。データの移行や削除は要らない。

## 検証の区別

- 単体テスト（Vitest）: fetch と回数計上を差し替えた合成応答だけ。実 API・実 DB には接続していない。
- 回数計上（`claim_dinner_ai_call`）と停止の印（`mark_dinner_ai_exhausted`）の RPC は DB 側の検証の対象で、この文書の範囲外。
- アダプターを画面の操作（Server Action）へつなぐ部分は別に検証する。
- **実 API 試験は未実施。** 無料経路であること（Workers Free）の確認も未実施で、人の作業として残っている。

### 未確認の点

- 3036 などのエラー本文の正確な形。公式のエラー一覧は内部コードと HTTP ステータスだけを示す。
  アダプターは `errors[].code`（数値・数字の文字列）を読み、読めないときは本文中の `"code": 3036` の形と公式の文言で補う。
  どれにも当たらない 429 は一時的な混雑として扱うため、形が想定と違うと枯渇を検知できず、停止の印が書かれない
  （Workers Free なら課金は起きないが、各操作が 2 回ずつ失敗して世帯の回数を消費する）。実 API 試験で確かめる。
- 既定モデルが `json_schema` の `enum` を守る度合い、日本語の精度。
- 分単位のレート制限（300 回/分）を超えたときの内部コード。
