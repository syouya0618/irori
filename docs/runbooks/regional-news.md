# 地域ニュース

## 利用者の操作

育児の「ニュース」、または設定の「地域ニュース」から地域を選んで保存する。初期値は未設定・通知OFF。掛川は市のお知らせ・施設のおたより・居場所/こども食堂の3配信元、札幌・横浜は各1配信元を利用する。

保存直後に取得済みの記事が見える。未取得なら「配信元から記事を更新」を押す。GET表示やprefetchでは外部取得を行わない。取得はサーバの配信元別lease/cooldownでまとめられ、手動操作はPushを送らない。年齢不明の記事は除外せず、「年齢の絞り込みを外す」で全記事に戻れる。

配信元別に未取得・取得中・最終成功時刻を示す。一部/全取得失敗、25時間以上前のキャッシュを区別する。掲載日は開催日ではなく、掲載日不明の記事は新着通知に使わない。取得済み最新100件を表示し、必ず原文を確認する。

## 必要な設定と通知

既存のSupabase接続だけでRSSの一覧・更新を使える。AI・VAPID・Push許可は記事閲覧の必須条件ではない。通知は本人の明示設定と端末のPush許可、運用側のVAPID設定が揃った場合だけ。既存の5分cronとJST朝8時の配信窓を使い、OSへの8時ちょうどの到着を保証しない。VAPID不足を通知成功とは扱わない。

## 任意のAI補助（既定OFF）

AIなしでRSSを閲覧・更新できる。使う場合だけ `NEWS_AI_ENABLED=true`、`NEWS_AI_ACCOUNT_ID`、`NEWS_AI_API_TOKEN` をサーバ側へ設定する。`NEWS_AI_DAILY_CALLS` は1〜20（既定20）。設定不足・429・認証失敗・タイムアウト・不正出力では原文タイトルと出典へ戻り、課金APIへ自動切替しない。

既存サーバからCloudflare Workers AIの `@cf/meta/llama-3.2-3b-instruct` を呼ぶ。公開見出しから固定語彙だけを抽出し、家族情報・氏名・本文・認証情報は送らない。補助は「要点（AI補助）」と明示し、日時や制度を生成しない。共有DBキャッシュと日次回数制限を使う。AI設定後に新しく取り込んだ記事が対象で、既存記事を後から再生成しない。検証済みの成功結果だけを共有キャッシュし、推論失敗も日次予算を消費する。次の配信元更新時に予算内で再試行できる。

方式比較: [Gemini無料枠](https://ai.google.dev/gemini-api/docs/pricing) は製品改善への内容利用が記載される一方、Workers AIはオプトインしない限り学習に使わないと説明する。今回は既存サーバからRESTを呼べて、専用Workerのデプロイが不要なWorkers AIを選んだ。

[公式料金](https://developers.cloudflare.com/workers-ai/platform/pricing/) の無料枠はアカウント全体で1日10,000 neurons。回数制限は無料枠内を保証するものではなく、他の利用も合算される。[モデル条件](https://developers.cloudflare.com/workers-ai/models/llama-3.2-3b-instruct/) と [データ利用条件](https://developers.cloudflare.com/workers-ai/platform/data-usage/) を運用者が確認する。今回、契約・実API有効化・課金変更は行っていない。

## DBからアプリへの更新

この変更は本番適用を含まない。正式な本番承認・バックアップ・リリース手順のもとで次を行う。

1. 実際の適用履歴と `supabase/migrations/` を照合する。従来の53本に加え、`20261101090000_news_multiple_sources.sql` → `20261101100001_news_optional_ai.sql` の2本を順に適用する（今回の合計55本）（並行変更があれば実ファイルを基準に再計数）。既存migrationは編集しない。
2. migrationは掛川の地域/URL制約、配信元別状態・claim、設定保存と状態読取りRPCを更新する。既存の札幌・横浜設定や通知ON/OFFは保持する。
3. DB適用後に、このDDLに対応するアプリを配信する。未適用DBへ新アプリを接続しない。作業ブランチの自動Previewは停止する。
4. 認証済み合成利用者で地域保存・再読込・更新・通知OFF・地域切替を確認する。本番利用者への試験Pushは行わない。

戻す場合はまずアプリの配信を以前の版へ戻し、追加テーブル/列/関数は保持する。旧版の札幌・横浜書込みは互換トリガーで配信元を補う。掛川を選択済みの利用者は旧版では扱えないため、ニュース利用を一時案内し、設定を勝手に別地域へ変更しない。DDLの逆適用や記事の削除はこの手順に含めない。

## 配信元と利用条件

掛川市が公式ページから案内するRSSを低頻度で読む。保存・表示は見出しと原文リンクを中心とし、記事本文・画像を転載しない。AIにも自由文を送らない。[市の著作権案内](https://www.city.kakegawa.shizuoka.jp/gyosei/docs/7685.html) は私的使用・引用等の法定例外を除く無断転載を禁じている。RSS公開を無制限の再配布許諾とは扱わない。`/kakekko/use` の個別案内は今回のWeb取得で確認できておらず、独立したライセンス確認済みとはしない。

## 検証の区別

- 2026-11-01の低頻度公開読取り: 掛川3RSSはHTTP 200、最終URL変更なし、UTF-8 RSS 2.0。順に20/20/19件、6801/6755/6070 bytes。実記事本文・人名はfixtureに保存していない。
- 単体/CIは固定時計と合成RSSで再現する。実フィード取得成功とAuth/RLS/ブラウザ操作の成功は別の証拠。
- Playwrightの390px/desktopはブラウザ試験であり、iPhone実機やPWAホーム画面確認ではない。
