## 変更と観測の対応

- settingsの子ども取得を初期照会と並列化。育児SSRの「いつもの量」は取得済みの児から読み、追加照会を除く。
- Supabase SSRクライアントと認証claimsはReact.cacheで同じリクエスト内に限って共有する。児IDはキャッシュ引数。時間ベース・プロセス全体の本人キャッシュは設けない。
- 親layoutに持続するSuspenseを置き、遷移時には既に表示した内容を保つ。cold表示には経路別skeletonを使う。Reactのfallback再表示の待ちを避けたことと、約330→50msの観測が対応する。
- 下部ナビは明示的なpending表示を持つ。partial shellの不要なprefetchは止める。dynamicの10秒TTLを変更せず、full prefetchによる長いキャッシュも追加しない。
- 成長データ・グラフは初回展開時に遅延ロード。見出しの最新値は開く前から表示する。
- 通常の育児初回のserver API数は35→26、設定hard navigationは25→17。育児→予定は9→7。server API span中央値は同順に155→134、74→74、21→10ms。背景処理も含むため、spanをcritical pathや実DB時間と読み替えない。

[React Suspense](https://react.dev/reference/react/Suspense) と [React cache](https://react.dev/reference/react/cache) の契約、およびインストール済みReact 19.2.8・Next.js 16.4.3の実装／同梱guideを確認した。新たな時間ベースの認証キャッシュは導入していない。

## 測定方法と再現

`scripts/measure-navigation.mjs OUTPUT.json --trials=5`。合成URL・合成公開キーでproduction buildを作り、同じ設定で起動する。環境ファイルのあるcheckoutは拒否し、自分で起動したNextプロセスのReadyを待つ。出力先は必ずオプション以外の引数で指定する。

- アプリ `127.0.0.1:55438`、合成API `127.0.0.1:55439`。実DBや実Authへ接続しない。外部へのブラウザ要求を遮断し、Service Workerを止める。
- Chrome 390×844、ja-JP、JST。4条件×5個の新しいbrowser context。版ごとに1個の起動済みNextサーバで、計125操作ずつ。
- 通常30件、800件、4児、低速回線。800件はHTTP fixtureの件数であり、DBの負荷試験ではない。
- 低速回線はブラウザRTT150ms、下り128KiB/s・上り64KiB/s、API応答ごとに200ms追加。
- タップはpointerdownから、遷移先の意味のあるDOMが見える最初のanimation frameまで。自動操作の待機完了とは別の指標。
- APIのリクエスト数・処理時間の合計・最初から最後までのspanをserver/browser別に集計する。描画後の静穏待ちまで含むため、背景照会が入る。
- 「初回育児」は新規context。「設定の初回」は同じcontext内のhard navigationで、既に取得したassetがある。サーバプロセスのcold start試験ではない。
- `useReportWebVitals` は端末内で明示的に有効にした時だけCustomEventへ必要な数値を出す。URL・児ID・利用者ID・計測entry・外部送信を含めない。初期LCP snapshotを最終LCP合格とは扱わない。

比較元でも同じframe observerの測定ロジックを用いた。最終版は環境ファイル拒否と起動プロセスの所有確認を追加している。旧Phase 1の一試行の値とは定義が異なり、直接比較しない。

実Supabase・実回線・実端末・PWA復帰・ネットワーク復旧・長期履歴での受入は別途必要。未実行の実E2Eをこの結果で代用しない。
